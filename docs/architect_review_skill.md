# 📐 Animora: Инструкция для Архитектора и Код-Ревьюера (Architect & Reviewer Skill)

> [!IMPORTANT]
> Эта инструкция описывает жесткий протокол контроля качества кода, архитектуры и ведения журналов для ИИ-Архитектора проекта Animora. Все изменения кода перед окончательным слиянием должны проходить проверку по этому протоколу.

---

## 🔍 Чек-лист проверки кода (Code Review Checklist)

### 1. Архитектурная чистота (Separation of Concerns)
*   **Слой UI (presentation/):** Виджеты НЕ должны напрямую обращаться к клиенту `Supabase.instance.client` или выполнять SQL/HTTP-запросы. Весь доступ к данным осуществляется исключительно через чтение/прослушивание Riverpod-провайдеров (`ref.watch`, `ref.read`).
*   **Слой данных (providers/):** Провайдеры должны инкапсулировать всю логику работы с Supabase API, обрабатывать ошибки и возвращать чистые структуры данных (Map или модели).
*   **Маршрутизация (core/navigation):** Вся навигация выполняется через именованные маршруты `GoRouter` (например, `context.go('/owner/pets')`). Прямое использование `Navigator.push` разрешено только для вспомогательных диалогов и BottomSheet.

### 2. Стандарты Riverpod 3.0+
*   Использование классов `StateNotifier` и `StateNotifierProvider` **СТРОГО ЗАПРЕЩЕНО** (они удалены в новых версиях).
*   Все классы состояний должны наследоваться от `Notifier<T>` или `AsyncNotifier<T>`.
*   Объявление провайдеров должно осуществляться через `NotifierProvider`.
*   Пример правильной структуры:
    ```dart
    class MyNotifier extends Notifier<MyState> {
      @override
      MyState build() => MyState(); // Инициализация
    }
    final myProvider = NotifierProvider<MyNotifier, MyState>(() => MyNotifier());
    ```

### 3. Локализация и Тексты
*   В файлах UI-экранов **запрещен хардкод текстовых строк** на русском или казахском языках.
*   Все строки интерфейса должны выводиться через метод `tr('key')` пакета `easy_localization`.
*   При добавлении нового текста на экраны, новые ключи и их переводы должны быть синхронно внесены в оба файла локализации: `assets/translations/ru.json` и `assets/translations/kk.json`.

### 4. Дизайн и Эстетика (Material 3)
*   Интерфейс должен строго следовать токенам нашей дизайн-системы, описанной в `lib/core/theme/app_theme.dart`.
*   Все интерактивные элементы должны иметь скругления углов (`BorderRadius.circular(14)` или `16`).
*   Кнопки действий должны использовать `ElevatedButton.styleFrom` с отключенным `elevation` и явным указанием `minimumSize` для удобства нажатия на мобильных устройствах.
*   Каждый асинхронный процесс (загрузка данных, вход в систему, бронирование) обязан отображать индикатор загрузки (`CircularProgressIndicator`) и блокировать повторные нажатия кнопок.

## 📝 Протокол ведения журналов и документации

После проведения код-ревью и подтверждения изменений Архитектор обязан:
1.  Убедиться, что в `docs/task.md` обновлен статус выполненных задач.
2.  Добавить запись в таблицу **«Журнал отладки (Debug Journal)»** в [docs/project_state.md](file:///c:/Projects/docs/project_state.md), если в процессе были исправлены баги или синтаксические ошибки.
3.  Обновить дерево файлов в карте проекта [docs/project_state.md](file:///c:/Projects/docs/project_state.md), если были созданы новые файлы или удалены старые.
