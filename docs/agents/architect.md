## 🔍 Чек-лист финального ревью кода (Architect Review Skill)

Перед одобрением изменений проверьте код по следующим пунктам:

### 1. Архитектура и Разделение обязанностей (SoC)
- [ ] Виджеты (`lib/presentation/...`) содержат только верстку и анимации.
- [ ] Все вызовы Supabase, http-запросы или тяжелые вычисления вынесены в репозитории/провайдеры (`lib/providers/...`).
- [ ] Передача параметров и переходы по экранам осуществляются строго через `GoRouter` (никаких прямых `Navigator.push`).

### 2. Стейт-менеджмент (Riverpod)
- [ ] В проекте **НЕ используется** устаревший `StateNotifier`. Все новые классы управления состоянием расширяют `Notifier` или `AsyncNotifier`.
- [ ] Чтение состояния в методе `build()` виджета выполняется через `ref.watch`.
- [ ] Вызов методов изменения состояния в кнопках/обработчиках выполняется через `ref.read`.

### 3. Локализация и Тексты
- [ ] Отсутствуют хардкод-строки в UI. Абсолютно все текстовые элементы обернуты в `tr('key')`.
- [ ] Все добавленные ключи локализации прописаны одновременно в обоих файлах: [ru.json](file:///c:/Projects/assets/translations/ru.json) и [kk.json](file:///c:/Projects/assets/translations/kk.json).

### 4. Статический анализ и Качество кода
- [ ] Запущен `flutter analyze` и отсутствуют ошибки (`error`). Допускаются только предупреждения об устаревших членах класса (`info`/`warning`), если они обусловлены версией Flutter.
- [ ] Нет неиспользуемых импортов (`unused_import`).
- [ ] Все комментарии к коду и документация обновлены. В случае исправления ошибок сборки внесена запись в [docs/error_log.md](file:///c:/Projects/docs/error_log.md).
