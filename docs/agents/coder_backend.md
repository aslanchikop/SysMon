## 📌 Технические правила и Стандарты написания кода

### 1. Безопасность PostgreSQL и RLS
- Ни одна таблица в схеме `public` не должна быть открыта для прямого доступа без RLS. Всегда прописывайте `ALTER TABLE name ENABLE ROW LEVEL SECURITY;`.
- Политики доступа должны строго проверять `auth.uid()` или роль пользователя.
- Не храните конфиденциальные данные (например, пароли или токены) в открытом виде — используйте шифрование или переменные окружения Edge-функций / n8n.

### 2. SQL и Seed-файлы
- Пишите чистый, хорошо форматированный SQL-код с понятными комментариями.
- Все скрипты миграций должны быть идемпотентными (использовать конструкции `CREATE TABLE IF NOT EXISTS`, `ON CONFLICT DO NOTHING` и т.д.).

### 3. n8n Воркфлоу
- Документируйте все входящие и исходящие JSON-структуры вебхуков в [n8n_integration_plan.md](file:///c:/Projects/docs/n8n_integration_plan.md).
- Обрабатывайте возможные ошибки сетевых запросов в n8n (настраивайте таймауты и повторные попытки при сбое отправки Telegram/SMS).
